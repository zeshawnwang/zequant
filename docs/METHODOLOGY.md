## 一、核心认知 (10 条)

### 1. 参数调优 > 新功能堆叠

Calmar 提升的最大贡献全部来自重新调优已有参数，而非新增功能模块：

| 贡献来源 | ΔCalmar | 类型 |
|:--|:--:|:--|
| mf rf=5天 (原10天) | +1.3 | 参数重调 |
| 紧止损 6/8 (原8/10) | +1.2 | 参数重调 |
| trail=5% (原15%) | +14.3 | 参数重调 |
| composite 择时 | +0.9 | 新模块 |
| 市场广度 | +0.4 | 新模块 |
| recovery 修复 | +0.3 | 分配调整 |
| chip_v2信号/HMM/宏观叠加/行业中性/CompositePositionSizer/自适应rf/状态级trailing | 0 或负 | 新模块 |

**教训**: 在接入新功能前，先穷尽已有参数的搜索空间。

### 2. 参数敏感性非线形 — 断崖效应

```
trail=3% → Calmar=38.4
trail=4% → Calmar=31.5
trail=5% → Calmar=20.3
trail=6% → Calmar= 9.4  ← 断崖! (腰斩)
trail=7% → Calmar= 6.8
```

**教训**: 参数扫描必须有足够粒度，否则可能完全错过甜点区。

### 3. 单点最优 ≠ 组合最优

V2 单点消融中 trail=10% 是冠军(Calmar=3.66)，但组合优化中 trail=15% 胜出(Calmar=3.29)。原因：trail=10% 与 breadth 组合时间歇更大。

**教训**: 消融 + 组合搜索两阶段实验设计是必需的。不要相信单点消融的排名。

### 4. 子策略局部改进不能替代全局评估

chip_v2/osr_v2 信号在子策略层面更精准，但组合后 Calmar 从 20.3 降到 17.7。新增因子改变了入池股票的风险特征，影响了 MSS 层的分配逻辑。

**教训**: 子策略层面的任何改进必须在 MSS 组合层重新验证。

### 5. 同名机制不可叠加 — 双重压缩陷阱

CompositePositionSizer(trend×vol双维仓位) 叠加在 composite timing 上 → Calmar -1.0。两个机制在功能上重叠，形成双重仓位压缩。状态级差异化trailing叠加状态切换的时滞 → 全败。

**教训**: 新模块接入前必须检查是否与已有模块功能重叠。简洁性原则。

### 6. GA 适合弱结构空间，不适合强结构空间

128次 GA 搜索分配权重，无一超越手工设计。手工权重每个选择有市场逻辑支撑(bull多因子→bear筹码防御)，GA随机探索无法重建这种结构。

**教训**: GA 适用于因子权重(56维弱结构空间)，不适用于状态分配(4状态×6子策略，强结构空间)。

### 7. Recovery 是通用短板，有确定性修复

所有配置在 recovery(熊市反弹)中表现最差。修复方向：recovery ≠ 弱bull，recovery = 超跌反弹 → osr_d10 替代 mf 系列。

### 8. 止损紧化 + 高频调仓 + 紧止盈 是三位一体

这三个参数互相依存：rf=5 → 每周期利润小 → trail 必须紧(3-5%)才能锁住。紧止损6% → 减少大幅亏损。紧止盈5% → 高频兑现。**单独改任何一个无效，必须联动优化。**

### 9. 实盘 top_n 降级有稳定比例

research(top_n=50/40) vs live(top_n=10/8/6): Calmar 降幅约 44%，方向完全一致。这个比例可作为未来策略评估的锚点。

### 10. 市场广度 — 最朴素但最稳健

简单的 `breadth<0.35→降级oscillate` 在所有版本中稳定有效(+0.3~0.4 Calmar)，只用了已发生的 pct_change，无前视偏差，是真正可实盘的指标。

## 二、方法论框架

### 实验设计

1. **Phase 0**: 建立精确baseline，确保可复现
2. **Phase 1**: 单点消融 — 每项独立 × baseline，计算 ΔCalmar
3. **Phase 2**: 参数 grid search — 自动探索，Calmar-driven keep/discard
4. **Phase 3**: 贪婪组合优化 — 每次加入改善最大的候选，停止条件: 无 >0.5% 改善
5. **Phase 4**: 归因分析 — 状态分层收益、DD归因、子策略净值追踪
6. **Phase 5**: OOS 窗口验证 + walk-forward + 策略配置自动更新

### 必须做的检查

- ✅ 每个新参数都在全状态 space 下扫描
- ✅ 每个子策略改进都在 MSS 组合层评估
- ✅ 新模块接入前检查功能重叠
- ✅ 所有改进做 OOS(2024.07+) 窗口验证 + walk-forward(×3 滚动窗口)
- ✅ 交易成本敏感性测试 (TX ∈ 0.001~0.003)
- ✅ 实验脚本中的每个参数开关都确保正确传递
- ✅ logging 系统必须在 `import` 其他模块之前配置，避免日志丢失

### 避免的错误

- ❌ 消融实验时对其他参数不做隔离
- ❌ 信号构建了但未真正接入信号源
- ❌ 单点测试优异但不做细扫描就用作基线
- ❌ 假设 GA 能解决一切优化问题
- ❌ 通过 `| tail` 管道运行导致日志不写入文件
- ❌ TX 交易成本只在第一笔成立时扣除，而非每笔调仓都扣
