# 盘中止损巡检 — 实时行情 + 多数据源兜底

> 最后更新：2026-06-15

---

## 背景

收盘后信号生成时的止损检查依赖 `daily_bars` 的昨日收盘价。当某股票今日大涨/涨停时，昨日收盘价计算出的亏损是**虚假的**，会导致错误卖出信号（如宝鼎科技、风华高科的案例）。

**解决方案：** 盘中用实时行情巡检止损，独立于收盘后的信号生成流程。

---

## 架构

```
收盘后 15:30                    盘中 09:30-15:00（每30分钟）
      │                               │
  mss_dynamic                     stop_monitor.py
      │                               │
  1. 更新数据                       1. 读 sub_strategy_state 持仓
  2. 算因子                          2. 拉实时价（多源兜底）
  3. 生成买卖信号                     3. 逐只检查止损/止盈
  4. 输出 build.json                 4. 触发→输出卖出指令
      │                               │
      ▼                               ▼
  信号文件                        止损记录文件
  build.json                      stop_signal.json
```

## 实时行情数据源

三个数据源依次尝试，第一个成功返回的即被采用：

| 优先级 | 数据源 | 接口 | 特点 |
|:-----:|:-------|:-----|:-----|
| 1 | **新浪财经** | `hq.sinajs.cn/list=sh600000,sz002416` | 轻量，按需请求少量股票，速度快 |
| 2 | **腾讯财经** | `qt.gtimg.cn/q=sh600000;sz002416` | 轻量，格式简单稳定 |
| 3 | **akshare** | `stock_zh_a_spot_em()` | 全市场快照（重），只作为最后兜底 |

数据源切换完全自动，每层 5 秒超时，全部失败时回退到 `daily_bars` 数据库。

## 盘中止损巡检

### 止损规则

与 `mss_signal.py` 完全一致：

- **固定止损**：从成本价亏损超过配置阈值（mf 系列 6%，chip 系列 8%）
- **移动止盈**：从持仓最高价（peak）回撤超过 3%

### 盘中的额外逻辑

- **peak 自动更新**：盘中价格创出新高时，自动更新 `sub_strategy_state` 中的 peak 值
- **非交易时间跳过**：周末、节假日、非交易时段自动跳过
- **无副作用**：不改变持仓，只输出卖出指令（由你决定是否执行）

### 调用方式

```bash
# 盘中巡检（自动检测交易时间）
python3 -m live.stop_monitor

# 强制巡检（跳过交易时间判断）
python3 -m live.stop_monitor --force

# 输出到文件
python3 -m live.stop_monitor --output data_live/stop_signal.json
```

### 自动化（cron）

用法:
```
*/30 9-14 * * 1-5  cd /path/to/zequant && python3 -m live.stop_monitor --output data_live/stop_signal.json
```

巡检频率：每 30 分钟一次（交易日上午 09:30-11:30，下午 13:00-15:00）。
非交易时间自动跳过，不影响。

## 与现有流程的关系

| 项目 | 收盘后信号（mss_dynamic） | 盘中止损（stop_monitor） |
|:----|:------------------------|:------------------------|
| 运行时间 | 每日 15:30 后 | 盘中 09:30-15:00 每 30 分钟 |
| 数据源 | daily_bars（日频因子） | 实时行情 API |
| 决策范围 | 全市场选股 + 调仓 + 止损 | 仅持仓股票止损/止盈 |
| 输出 | 完整买卖清单 | 仅止损/止盈卖出指令 |
| 执行方式 | 手动（record.py 录入） | 手动（参考后决定） |
