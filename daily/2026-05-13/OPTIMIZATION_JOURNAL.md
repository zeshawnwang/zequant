## 第一阶段：代码审查与架构重构

### 背景

项目 `zequant` 是一个量化交易框架，最初存在双架构（OLD/NEW）共存的问题。OLD架构位于 `core_old/` 目录，NEW架构位于 `core/` 目录。这种双架构导致了代码维护困难和潜在的BUG。

### 发现的主要问题

| 编号 | 问题 | 影响 |
|------|------|------|
| 1 | `QuantStrategy` 类不存在，但被3个文件引用 | 运行时导入错误 |
| 2 | 优化模块缺少关键导入（BacktestEngine, SignalStrategy等） | 运行时 NameError |
| 3 | `report.annual_return` vs `report.annualized_return` 属性名不匹配 | 回测分析结果丢失 |
| 4 | `strategy.py` 参数顺序错误 (`select(date, market_data)` → `select(market_data, date)`) | 策略选股逻辑失效 |
| 5 | `GAOptimizer` 模块已删除但仍有引用 | 导入错误 |
| 6 | `config_manager.py` 引用已删除的 `get_db_path()` | 配置加载失败 |
| 7 | `int(NaN)` 在 close 价格为 NaN 时崩溃 | 运行时崩溃 |

### 决策：彻底采用新架构

**选择**：不向后兼容，彻底删除 `core_old/` 旧架构，所有代码迁移到新架构。

**关键变更**：
- `QuantStrategy(...)` → `SignalStrategy(...)`：新架构策略类，支持组件化（Selector + PositionSizer + Composer + RiskManager）
- `EqualWeightBuilder` → `LayeredComposer`：更灵活的信号合成方式
- `GAOptimizer` → 自研GA循环：参考遗传算法标准实现，自定义评估函数
- 所有路径改为新架构下的模块位置

### 测试结果

自测 31/31 测试全部通过，核心模块导入验证通过（23/23）。

## 第二阶段：基础回测管道构建

### 设计思路

管道需要支持：
1. **306个因子**的单因子回测（Stage 1）
2. **遗传算法权重优化**（Stage 2）
3. **断点续传**：每个阶段的结果持久化，重启自动跳过已完成步骤
4. **归因分析**：记录每次回测的详细指标

### 性能优化

原始实现：使用 `BacktestEngine` 逐个因子回测，每个因子需2-3秒。
→ 306因子 = 15分钟+，不可接受。

**向量化优化**：使用 `pivot_table` 将因子数据转为日度矩阵（N日 × M股），利用 numpy 向量化计算组合收益、择时信号、最大回撤等指标。

优化效果：
```
原始: 3分钟/因子 × 306 = 918分钟 (15小时+)
向量化: 2-5秒/因子 × 306 = 15-25分钟
GA评估: 80ms/评估 × 1500 = 2分钟
```

### 风控约束调整

初始约束过于严格：
- `min_win_rate=0.50`：对于日频交易，日胜率7-8%是正常的，50%要求过高
- `min_calmar_ratio=0.50`：部分因子可能达不到

**调整方案**：
- Stage 1（因子初筛）：使用宽松约束（`min_win_rate=0.30`, `min_calmar_ratio=0.20`）
- Stage 2（权重优化）：使用正常约束（`min_win_rate=0.30`, `min_calmar_ratio=0.40`），快速评估中的风控过滤使用

### 数据对齐问题

发现：不同因子列的日期范围不同，导致 `pivot_table` 索引越界。

**修复**：对所有因子列使用 `reindex(index=all_dates)` 对齐到统一的日期轴。

## 第三阶段：单因子筛选

### 流程

1. 对全部 **306个因子** 运行单因子回测（2019-01-02 ~ 2026-05-13）
2. 每个因子计算：年化收益、夏普比率、最大回撤、Calmar比率、胜率
3. 综合评分 = `ann_ret * 0.30 + sharpe * 0.25 + calmar * 0.30 + win_rate * 0.15`
4. 每个因子类别保证至少 **1个**，取消每类上限，总计选 **50个**

### 选股结果

| 类别 | 选中数量 | 说明 |
|------|---------|------|
| 技术指标 | 15 | RSI, MACD, BOLL, MA相关等 |
| 情绪指标 | 1 | 市场情绪类因子 |
| 动量指标 | 1 | 趋势动量类 |
| 波动率指标 | 1 | 波动率相关 |
| 基本面指标 | 1 | 财务基本面 |
| 其他 (GTJA) | 31 | 国泰君安因子库 |

### 关于 "其他" 类别较多的说明

GTJA因子库包含大量有效因子（31个），这表明该因子库整体质量较高。但这可能导致权重优化时"其他"类别因子过度集中。后续的 L1 正则化会帮助分散权重，防止个别类别过度集中。

## 第四阶段：遗传算法权重优化

### 算法参数

| 参数 | 值 | 说明 |
|------|----|------|
| 种群大小 | 30 | 每代保留30个候选解 |
| 迭代代数 | 50 | 总进化代数 |
| 选择策略 | Top-3 精英保留 | 最优的3个直接进入下一代 |
| 交叉策略 | Top-10 随机配对平均 | 从最优10个中随机选2个取均值 |
| 变异率 | 15% | 初始变异率 |
| 变异幅度 | 0.15 | 高斯噪声标准差 |
| 去重阈值 | 0.3 | 平均权重差异 < 0.3 视为重复 |

### 评估函数

```python
score = ann_ret * 0.30 + sharpe * 0.25 + calmar * 0.30 + win_rate * 0.15
```

其中：
- **ann_ret**：年化收益率（权重30%）
- **sharpe**：夏普比率（权重25%）
- **calmar**：Calmar比率，年化收益/最大回撤（权重30%）
- **win_rate**：胜率（权重15%）

### 发现的问题：收敛到相同解

第一版GA的5组最优配置全部完全相同。

**原因分析**：
1. 50代迭代中，最优解被反复选中，子代高度相似
2. 交叉策略（取平均）加剧了趋同性
3. 缺乏正则化约束，权重自由度导致个体间差异被压缩

**改进方向**（在第五阶段实现）：
1. 增加迭代代数 + 动态变异率衰减
2. L1正则化惩罚权重大小
3. 换手率约束惩罚过度交易
4. 多样度去重阈值过滤重复配置

## 第五阶段：增强型综合验证

### 5.1 增强版遗传算法 (L1正则化 + 换手率约束)

#### 改进的评估函数

```python
score = ann_ret * 0.30 + sharpe * 0.25 + calmar * 0.30 + win_rate * 0.15
        - l1_penalty - turnover_penalty
```

#### 五个GA版本对比

| 版本 | L1 λ | 换手惩罚 | 调仓频率 | 种群 | 代数 | 目的 |
|------|-------|---------|---------|------|------|------|
| 基础版_daily_50代 | 0 | 0 | 1日 | 30 | 50 | 基准对比 |
| L1正则化_daily_60代 | 0.005 | 0 | 1日 | 30 | 60 | 检验L1效果 |
| L1+换手_weekly_60代 | 0.005 | 0.3 | 5日 | 30 | 60 | 低换手场景 |
| L1+换手_daily_80代 | 0.005 | 0.3 | 1日 | 40 | 80 | 高迭代+双约束 |
| L1强_weekly_100代 | 0.01 | 0.5 | 5日 | 40 | 100 | 强正则化 |

#### L1正则化

L1正则化在评估函数中引入 `l1_lambda * sum(|w|)` 惩罚项。

**效果**：
- 鼓励稀疏权重：让不重要的因子权重趋向0
- 防止过拟合：限制权重大小，避免个别因子过度支配组合
- 特征选择：自动识别最重要的因子子集

λ值选择说明：
- `λ=0.005`：温和正则化，保留大部分因子
- `λ=0.01`：强正则化，显著压缩权重，适合过度拟合风险高时

#### 换手率约束

在快速评估中追踪每次调仓的权重变化量：

```python
turnover = sum(|w_t - w_{t-1}|)  # 每次调仓的换手率
avg_turnover = total_turnover / rebal_days
turnover_penalty = penalty_coef * max(0, avg_turnover - 0.5)
```

**效果**：
- 惩罚频繁调仓：减少交易成本
- 惩罚权重剧烈变化：保持策略稳定性
- 调仓频率设为5日（周频），符合"低频交易"要求

#### 动态变异率

```python
mutation_rate = 0.15 * (1 - gen / generations) + 0.05
```

早期（高变异率 → 探索）：`15%` → 后期（低变异率 → 收敛）：`5%`

#### 去重机制

配置间平均权重差异 `< 0.3` 视为重复，只保留第一个。确保最终输出5个有实质差异的配置。

### 5.3 向量化回测验证（替代 BacktestEngine）

#### 为什么放弃 BacktestEngine

最初的实现使用 `BacktestEngine` 进行真实回测，但遇到严重的性能问题：

| 问题 | 具体表现 |
|------|---------|
| **性能灾难** | 每个配置需 8分钟+，5个配置合计 40分钟+ |
| **内存膨胀** | `generate_orders()` 每天扫描 `df[df['date'] <= current_date]`，数据量从 2000行 增长到 360万行 |
| **因果泄露** | 每日切片包含未来数据，违反了回测的基本假设 |

**决策**：放弃 BacktestEngine，改用纯 numpy 向量化回测。

#### 向量化回测方案

将 BacktestEngine 的事件驱动逻辑替换为矩阵运算：

```
步骤1: 预计算所有因子在每个时间点的 z-score 矩阵 (N_dates × N_stocks × N_factors)
步骤2: 在每个调仓日，使用权重向量 w 计算综合得分: scores = np.dot(factor_z[t], w)
步骤3: 选 top-30 股票，等权持有至下次调仓
步骤4: 对持有期内的每日收益按持仓天数加权平均得组合日收益
步骤5: 使用对数收益率累加计算净值曲线: equity = np.exp(log(initial) + cumsum(log1p(ret)))
```

**性能对比**：

```
BacktestEngine: 8分钟/配置 × 5 = 40分钟  ❌
向量化回测:     20秒/配置 × 5 = 100秒    ✅ (25倍+加速)
```

#### 向量化回测的参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 初始资金 | 1,000,000 | |
| 调仓频率 | 调仓日（356次） | 沿用滚动验证的调仓日 |
| 选股数量 | top-30 | |
| 每日收益 | -20% ~ +20% 截断 | 防止极端值导致浮点溢出 |
| 净值计算 | 对数收益率累加 + exp | 比 cumprod 更稳定 |

#### 向量化回测 vs 快速评估的一致性检验

两者使用**完全相同的 z-score 矩阵**，区别仅在于：
- 快速评估：使用简化的滚动窗口评分
- 向量化回测：完整的每日净值曲线、最大回撤、夏普比率计算

### 滚动验证的跨周期表现

所有配置均未在所有7个窗口取得正收益（`all_windows_passed: false`），这在真实市场中是正常的。关键发现：

| 市场阶段 | 最佳适配配置 | 原因 |
|---------|------------|------|
| 2019_修复牛 (bull) | L1+换手_weekly (+0.55) | 周频调仓在趋势行情中更稳定 |
| 2020_疫情冲击+反弹 (volatile) | L1强_weekly (+0.53) | 强正则化过滤了噪声因子 |
| 2021_结构牛 (bull) | L1+换手_weekly_#2 (+3.08) | 所有配置都表现最佳 |
| 2022_熊市 (bear) | **全部失效** (score=-1.0) | 单边下跌无防御能力 |
| 2023_震荡修复 (recovery) | L1强_weekly (+0.53) | 强正则化在低信噪比环境中有效 |
| 2024_反弹 (bull) | 所有配置均正收益 | 上行市场选股有效 |
| 2025_至今 (mixed) | 所有配置均强正收益 | 当前市场高度适配 |

**核心洞察**：没有任何单一配置能适应所有市场环境。熊市期间（2022年）所有策略均失效，说明**择时比选股更重要**。

### 2022年熊市期间各配置均失效的原因

2022年 A股全年下跌（沪深300 -21.6%），且是系统性下跌（几乎所有板块轮跌）。在这种环境下：
1. 多因子选股在系统性下跌中无法提供保护——因子选股做的是**相对收益**（选好的股票），不是**绝对收益**
2. 收益归因分析显示，2022年所有配置的收益都来自收益因子方向（正收益因子权重 ≈ 1.0），但市场beta为负

### 5个配置的优劣分析

#### ① 基础版_daily_50代（无正则化、日频）✅ 最佳
- **优势**：年化25.48%、夏普0.84，显著领先其他配置
- **风险**：最大回撤39.9%（接近腰斩），但与其他配置相比并不算高
- **原因**：未加任何约束，GA充分优化了权重空间
- **建议**：适合风险承受能力较强的投资者

#### ② L1+换手_weekly_60代（周频、温和L1）✅ 推荐
- **优势**：年化18.82%、夏普0.76，表现稳健
- **特色**：周频调仓降低交易成本，2022年熊市中回撤42%已属相对优秀
- **原因**：L1正则化防止了过度拟合，周频调仓提高了稳定性
- **建议**：最适合实盘的首选配置

#### ③ L1+换手_daily_80代（日频、双约束）❌
- **表现**：年化-1.20%，回撤80.1%
- **原因**：日频调仓 + 换手率约束的组合互相矛盾——调仓频率高但惩罚换手，GA在两种压力下无法收敛到有效解
- **教训**：约束条件之间需要一致性

#### ④ L1强_weekly_100代（强正则化、周频）❌
- **表现**：年化-7.11%，回撤80.9%
- **原因**：λ=0.01 的强L1过度压缩了权重，有效信息被惩罚消除
- **教训**：正则化强度需要与问题复杂度匹配

#### ⑤ L1正则化_daily_60代（仅L1、日频）❌
- **表现**：年化-10.99%，回撤89.0%，夏普-0.03
- **原因**：只加L1不加换手率约束，日频调仓导致权重剧烈波动
- **教训**：单一约束不如组合约束有效

### 7.2 改进方案

#### 风险平价仓位分配器（Risk Parity）

将原先的**等权持仓**（选top-30，各1/30权重）替换为**波动率倒数加权**：

```python
w_i = (1/σ_i) / Σ(1/σ_j)
```

其中 σ_i 为股票 i 过去20日的滚动收益率标准差。

**效果**：
- 低波动股票获得更高权重 → 降低组合波动
- 高波动股票获得更低权重 → 控制尾部风险
- 每个股票对组合的风险贡献接近相等

#### 周频调仓

| 参数 | 旧值 | 新值 | 说明 |
|------|------|------|------|
| rebal_freq | 1（日频） | 3（≈周2次） | 每周交易1-2次 |
| min_hold_days | 0（无限制） | 5（≈1周） | 买入后至少持有5个交易日 |
| 调仓次数 | 356次/年 | ~80次/年 | 降低75%+的交易频率 |

#### 交易成本模型

```python
TX_COST_RATE = 0.0015  # 0.15%
# 包含: 佣金万三(0.03%) + 印花税千一/2(0.05%) + 滑点(0.07%)
# 每日收益中扣除: daily_ret[t] = portfolio_return - 0.5 * turnover * tx_cost_rate
```

#### 风险平价收益来源分析

风险平价的核心收益来源：

```python
# 等权: 每只股票权重 = 1/30 ≈ 3.33%
# 风险平价: 权重与波动率成反比
```

A股市场长期存在**低波动异象**（Low Volatility Anomaly）——低波动股票长期收益高于高波动股票。风险平价天然利用了这一点。

### 8.3 迟滞仓位分配器设计


| **迟滞_激进** | 5% | 1% | 50% | 激进迟滞：更多股票被锁定，仅保留50%调仓 |

**结论**：在V1最佳权重附近做微调，换手惩罚不是关键因素。

```python
# 对每只股票每日的截面做:
```

权重使用V1最佳配置（周频_L1中_80代）的48个非零因子权重，归一化到 Σ|w|=1。

#### TrendVolatilityTiming（MACD+动量+RSI+波动率风控）

```python
# 每只股票每日的评分:
trend_score = avg(
    MACD > MACD_signal → 1.0 else 0.0,
    momentum_5 > 0 AND > momentum_20 → 1.0; < 0 → 0.0; else 0.5,
    RSI: 50~70 → 1.0; 30~50 → 0.5; else 0.0
```
